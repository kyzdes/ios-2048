Designer notes

What's locked in (per §7)

  • Palette: #FAF8EF bg, #776E65 ink, #BBADA0 board, #CDC1B4 cell, #8F7A66 button, #EDC22E gold — verbatim from GamePalette.swift
  • Tile colours 2 → 2048 reused exactly from TileView.swift
  • Icon used as wordmark glyph and favicon — AppIcon-mac-256.png
  • Font: -apple-system / SF Pro Rounded / Avenir system stack — no webfont
  • Density: restrained · narrative: hero · distance: 1m laptop · temperature: warm

What's varying (§8.4)

  • DIM 1 · Hero composition — A: split text-left + board-right · B: centered single column · C: full-bleed board-as-hero
  • DIM 2 · Live board — A: auto-loop caption only · B: tap-to-play affordance · C: keyboard hint shown, playable from first paint
  • DIM 3 · Download cards — A: DMG primary + ZIP secondary · B: DMG only (ZIP in disclosure) · C: DMG · ZIP · iOS equal-weight row
  • All three keep the same feature chips, how-to-play structure, footer columns — only the §8.4 dimensions differ, so the comparison is clean

Caveats & next steps

  • Board auto-play is a 10-snapshot deterministic loop, not a real game engine — looks like the spec's "recorded sequence" intent. For Variant C, "fully playable" affordance is shown via the keyboard chip; real arrow-key handler is a 60-line add
  • The board is decorative — aria-hidden in production; once promoted to Play mode (Variants B/C) it gets role="application"
  • Variant C mobile shows §10.4 wrong-platform mode — primary CTA swaps to iOS-notify; no DMG offered to phones
  • SHA-256 strings are placeholders — real values come from script/release.sh at build time
  • If you lock Variant A or B, archive the other two in §9.5 of the spec; the §8.8 lock-in template is ready to paste
